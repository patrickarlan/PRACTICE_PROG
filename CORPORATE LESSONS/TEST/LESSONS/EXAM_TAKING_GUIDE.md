## 📝 HOW TO ANSWER EACH TYPE

### Multiple Choice
- Read all options before answering
- Eliminate obviously wrong answers first
- If unsure, pick the most reasonable answer
- Move on - don't spend > 1 min per question

### True or False
- Be careful - "always" and "never" are usually false
- Think of one counterexample to disprove
- 30 seconds per question max

### Short Answer
- Write complete but concise answer
- For syntax questions: Show exact code/command
- For explanations: 1-2 sentences max
- 2 minutes per question

### Debugging Activity
- Step 1: Identify error type (Syntax/Logic/Runtime)
- Step 2: Find the exact line with the problem
- Step 3: Write the fix
- Step 4: Explain why it was wrong
- 3-5 minutes per debugging question

### Coding Challenge (Q40)
- Step 1: Read requirement carefully
- Step 2: Write pseudocode (English outline)
- Step 3: Write actual code
- Step 4: Check for syntax errors
- Step 5: Trace through with example
- 10 minutes total

## 💡 SPECIFIC TIPS BY SECTION

### Section A - Logic
- These are foundational - should be quick
- Watch for order of operations (multiplication before addition)
- Remember arrays start at index 0
- Array of length 5 = indices 0,1,2,3,4

### Section B - PHP
- Remember `$` prefix for variables
- `.` for concatenation, not `+`
- `foreach` is simpler than `for` for arrays
- `echo` is more common than `print`

### Section C - MySQL
- Always think WHERE clauses (UPDATE, DELETE)
- COUNT(*) for row count
- WHERE conditions are AND/OR logic
- Data types matter (INT vs VARCHAR)

### Section D - Java
- Type declarations are REQUIRED
- `.equals()` for strings, not `==`
- Array indices start at 0
- `public static void main` is the entry point

### Section E - Debugging
- Read error message first - it tells you the line
- Identify error TYPE before fixing
- Boundary testing (edges, not just middle values)
- Missing WHERE means ALL rows affected

### Section F - Coding
- Don't rush - show your work
- Use meaningful variable names
- Comments are good (optional but shows understanding)
- Test with the example output

## 🎯 DURING THE EXAM

**Strategy:**

1. **Read all questions first (2 minutes)**
   - Skip around if something seems hard
   - Mark questions to review

2. **Do easy questions first (30 minutes)**
   - Sections A, B, C: These should be quicker
   - Build confidence
   - Get easy points first

3. **Do medium questions (35 minutes)**
   - Sections D and E: Require more thinking
   - Take your time, show your work
   - Don't rush

4. **Do hard questions (10 minutes)**
   - Section F: The coding challenge
   - By now you're warmed up
   - Focus on getting partial credit

5. **Review if time (10 minutes)**
   - Check for obvious errors
   - Verify you answered each question
   - Don't overthink changes

## ✍️ ANSWERING TECHNIQUES

### For Questions You're Unsure About:

**Option 1: Make an educated guess**
- Multiple choice? Pick most reasonable
- True/False? Look for absolute language ("always", "never")
- Short answer? Write what you think is closest

**Option 2: Skip and come back**
- Put a star (★) next to it
- Come back if you have time
- Don't leave blank

**Option 3: Show partial work**
- For debugging: Show you found the line (even if fix is wrong)
- For coding: Show pseudocode or partial code
- Partial credit is better than nothing

## 🚫 COMMON MISTAKES TO AVOID

| Mistake | How to Avoid |
|---------|-------------|
| Misreading question | Read carefully, underline key words |
| Wrong data type | Check type requirements |
| Forgetting WHERE clause | Ask "Does this affect ALL rows?" |
| Off-by-one in arrays | Remember: length 5 = indices 0-4 |
| Rushing the coding | Save coding for when mind is fresh |
| Leaving questions blank | Better to guess than leave blank |
| Trusting first impression | Re-read if unsure, verify logic |
